## Approach

The repository is a two-layer MVP (Spring Boot backend + Flutter frontend) and uses the native package manager for each layer independently. There is no cross-language dependency orchestrator (no Gradle multi-project, no Bazel, no Nx).

### Backend — Maven / Spring Boot
- Manifest: `backend/pom.xml`
- Parent POM: `org.springframework.boot:spring-boot-starter-parent:3.3.4` (declared via `<parent>` with `<relativePath/>`, so versions are inherited from the Spring Boot BOM rather than pinned individually).
- Java version pinned to `17` via `<properties><java.version>17</java.version></properties>`.
- Direct dependencies:
  - `spring-boot-starter-web` (REST)
  - `spring-boot-starter-data-mongodb` (MongoDB Atlas, per comment in file)
  - `spring-boot-starter-validation` (DTO validation)
  - `spring-boot-starter-security` (JWT-ready security)
  - `io.jsonwebtoken:jjwt-api/impl/jackson:0.12.6` (JWT library; impl and jackson modules scoped `runtime`)
  - `org.springdoc:springdoc-openapi-starter-webmvc-ui:2.6.0` (Swagger/OpenAPI docs)
  - `org.projectlombok:lombok` marked `<optional>true</optional>` and excluded from the Spring Boot Maven plugin's jar packaging via `<build><plugins><plugin>...<excludes><exclude>...</exclude></excludes></plugin></plugins></build>`.
  - Test-only: `spring-boot-starter-test`, `de.flapdoodle.embed.mongo.spring3x` (embedded MongoDB for tests).
- No custom `<repositories>` or `<pluginRepositories>` sections — relies on Maven Central through the Spring Boot parent.
- No lockfile (Maven does not ship one by default); transitive versions come from the Spring Boot BOM.

### Frontend — Dart/Flutter pub
- Manifest: `frontend/pubspec.yaml` — declares direct dependencies with caret (`^`) semver ranges.
- Lockfile: `frontend/pubspec.lock` — generated by `pub`, pins every transitive dependency to an exact version plus `sha256` hash, sourced from `https://pub.dev` (`source: hosted`).
- SDK constraint: `environment.sdk: '>=3.3.0 <4.0.0'`.
- Direct dependencies:
  - `flutter` (sdk), `cupertino_icons: ^1.0.6`
  - Maps/location: `google_maps_flutter: ^2.7.0`, `geolocator: ^14.0.2`
  - HTTP/state: `http: ^1.2.1`, `provider: ^6.1.2`
  - Image: `image_picker: ^1.1.2`
  - Push notifications (Firebase free tier, per comment): `firebase_core: ^4.15.0`, `firebase_messaging: ^16.7.0`
- Dev dependencies: `flutter_test` (sdk), `flutter_lints: ^5.0.0`.
- The app is not published (`publish_to: 'none'`).

### Android/iOS/Native toolchains
- Android Gradle wrapper present under `frontend/android/gradle/wrapper/` (`gradlew`, `gradlew.bat`, `gradle-wrapper.jar`, `gradle-wrapper.properties`).
- iOS/macOS/Linux/Windows platform targets are scaffolded by Flutter; their native build files reference Flutter-generated plugins but do not declare additional third-party deps beyond what Flutter resolves.

## Conventions observed

- Each language ecosystem owns its own manifest; there is no shared dependency graph between backend and frontend.
- Backend versions are managed centrally through the Spring Boot parent BOM — individual starter artifacts have no explicit `<version>` tag, while non-starter libraries (JWT, springdoc) pin exact versions directly.
- Lombok is treated as a compile-time-only annotation processor: declared `<optional>true</optional>` and explicitly excluded from the packaged artifact.
- Frontend uses caret ranges (`^`) in `pubspec.yaml` for flexibility, with `pubspec.lock` providing deterministic builds via sha256 hashes.
- All packages resolve from public registries only (Maven Central via Spring Boot parent; `https://pub.dev` for Flutter). No private registry, proxy, or vendored dependencies are configured anywhere in the repo.
